# Design Alignment Matrix (Team V2.0 General Design <-> Twin-Graph Implementation)

This document records how `workflow-orchestrator` implements the team's `通用Workflow编排系统_总体设计文档_V2.0.md` architecture while modernizing legacy abstractions where appropriate for real-time autonomous execution.

| Design Dimension | Team V2.0 Design Requirement | Implemented Architecture in `workflow-orchestrator` | Adaptation Note |
| :--- | :--- | :--- | :--- |
| **Entry Boundary** | Begins after confirmed user intent/requirements document (`Goal Spec`) | Markdown Requirements Doc import -> deterministic/assisted `GoalSpec` parser (`FR-xx`, `AC-xx`, inputs, outputs, constraints, tagged assumptions) | Excludes upstream conversational elicitation; treats confirmed PRD as input contract |
| **Spec & 3-Level Validation** | Structural, semantic/contract, and resource/policy validation (`Error` / `Warning` / `Info`) | `validateWorkflowSpec()` checks forward DAG cycles, `Start -> Done` reachability, `FR-xx` coverage, I/O contracts, parallel write-scope overlap, and capability health | Blocks Run launch when `Error` diagnostics exist or capability circuit is open |
| **Task Decomposition** | `Project -> Phase -> Task -> Subtask` hierarchy + explicit DAG dependencies + Planning Rationale | Hierarchical metadata (`phaseId`, `parentCode`, `depth`) unified inside compiled **Twin-Graph** (`dep`, `pass`, `fail`, `loop` edges) with per-node `planningRationale` | Avoids maintaining two disconnected graph engines; WBS tree and Flow DAG read from one canonical store |
| **Execution Substrate Abstraction** | Generic executor/adapter interface decoupled from concrete agents/tools | `CapabilityAdapter` + `ExecutorKind` (`agent`, `tool`, `human`, `control`) with `ResourceSlotBroker`, circuit breaker (`env_fault` vs `task_failure`), ACP/CLI/API & deterministic local tools | Replaces coarse `Factory/Line/Station/Token` analogies with fine-grained Twin-Graph node attempts and typed I/O contracts |
| **Dual-Mode Design & Impact Analysis** | Manual + AI co-editing with change impact assessment | Draft canvas/table editing (`updateDraftSpec`) + `analyzeChangeImpact()` computing downstream blast radius, affected `FR-xx`, and dirty validation state | Also supports safe live runtime `GhostNode` splicing during active runs |
| **Trial Run & Version Isolation** | Isolated dry run before production + immutable snapshot per Run | `runTrialSimulation()` simulates routing/contracts without mutating target workspace; `confirmWorkflowVersion()` freezes `v1`, `v2`, ... linked immutably to `runs.version_id` | Prevents mid-run drift when users continue editing drafts |
| **Orchestrator Engine** | Dependency Manager, Scheduler, Adapter, State Manager, Resource Broker, Recovery Controller, Journal | Event-driven `OrchestratorEngine` dispatching all `ready` parallel frontiers, `skipped` propagation on unselected branches, `Join` barriers, bounded rework (`Decision -> Restore -> Checkpoint`), Git Worktree isolation + rescue refs | Real `node:sqlite` + Git worktree process runner rather than design-only pseudo-code |
| **Human Control & Observability** | Unified Task List + Flow Graph + Node Detail + Activity Log; Pause/Resume/Retry/Intervene | Crisp Light DirectUI (`@xyflow/react` 12 + synchronized WBS & Flow Monitor + Node Inspector + live SSE stream + FTS5 audit search) | Cleanly separates **Design Mode** (`WorkflowsView`) from **Run Mode** (`WorkstationView`) |
