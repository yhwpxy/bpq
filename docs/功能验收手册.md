# 功能验收手册

本手册用于功能分支 `feat/parity-with-reference`。不需要商业模型即可演示核心真实执行链路。

## 1. 环境与启动

1. 安装 Node ≥18、npm、Git；准备可写磁盘。
2. 执行 `npm ci`、`npm run dev`。
3. 打开 `http://localhost:5173/#workbench`。原课程编辑器仍在根路径；点击品牌可进入完整工作台。
4. 使用“能力”页的“检查环境”核对 Git。配置探测与供应商真实访问分开显示。

## 2. 推荐课堂链路（约 8–10 分钟）

| 步骤 | 操作 | 应看到的证据 |
| --- | --- | --- |
| 1 | 点击“真实产物演示” | 三级任务树、两份报告任务、人工门禁、条件汇合、检查点和 Restore |
| 2 | 在树或画布选择任务，编辑名称与规划理由并应用 | 表单与画布同步；影响报告包含 FR 和下游节点 |
| 3 | 把 FR 引用改为 FR-999，点击检查 | R8 Error；点击诊断定位到该节点；恢复 FR-01 |
| 4 | 隔离试运行 | 展示模拟路径与 skipped；注明不会执行工作区命令 |
| 5 | 发布版本 | v1.0 快照可下载；试运行过期时不能发布 |
| 6 | 运行选定版本 | 实际创建独立 Git worktree；进入 waiting_human |
| 7 | 插入一个 GhostNode，填写理由；批准人工门禁 | 补充任务进入运行图，发布快照无 Ghost |
| 8 | 观察执行 | 两个实际文件产物；验证命令第一次故意失败；返工一次后通过 |
| 9 | 查看检查点、尝试记录、会话和日志 | 原失败尝试保留，恢复引用和旧目录可追踪 |
| 10 | 导出证据 | evidence JSON 含版本、运行图、尝试、会话、检查点、人工决定和校验摘要 |

内置演示文件为 `artifacts/fr-01/report.json` 和 `artifacts/fr-02/report.json`。脚本会核对其中的 `verified` 字段，不代表它已经实现任意业务需求。

## 3. 版本隔离与人工控制

- 在门禁等待时暂停，切回设计修改 GoalSpec，重新试运行并发布 v2.0；回到运行页，仍显示 v1.0。
- 刷新页面后从“运行”恢复观察，继续批准旧运行。
- 在另一次运行中拒绝门禁：运行失败，后续任务不执行，理由可在审计搜索中找到。
- 失败运行选择重试：只重置失败区域，保留历史 attempt 和此前成功节点。
- 已完成运行选择一个检查点恢复：先保存旧产物和 rescue 引用，在新 worktree 继续；不 reset 原分支，不删除旧目录。
- 自动返工耗尽进入人工等待。批准只追加一次额度；拒绝结束，不能通过默认 Resume 无限循环。

## 4. 契约、模板与导出

- 入口支持三个原创示例，也可上传 `.md/.txt`（200KB）。GoalSpec 列出 FR、AC、输入、输出、约束、模块和来源。
- 原文可核对项标为 doc；补充/模型归纳标为 suggested；人工确认后为 user_confirmed，同时保留 origin。
- 自然语言模式调用服务端 `LLM_*` 配置，提取完整 GoalSpec。原编辑器的自然语言 TaskSpec 接口保持原契约。
- 选择快速、完整、强化或自定义模板，设置人工门禁、扩展检查、QA、资源上限和预算。完整 QA 模板必须配置可用模型能力；未配置时显示阻塞诊断。
- “校验与版本”页可导出 Markdown WBS、Mermaid、Plan JSON。设计导出不是执行成功证明。
- 节点输入/输出契约使用 `{name,type,required}`。运行输入是 JSON 对象；显式必填输入缺失会拒绝运行。默认建议的 source 对象由工作区基线填充。

## 5. 能力与扩展模块

| 功能 | 操作与预期 |
| --- | --- |
| 能力池 | 登记 local/native/cli/acp，启停、编辑角色/提示词/命令，探测后查看状态；连续失败三次开路 |
| 模型 | 配置供应商协议、地址、模型与 Key；客户端只显示掩码；环境变量仍支持旧 LLM 入口 |
| CLI/ACP | 安装并配置实际程序后联调。测试已有可控子进程协议替身；没有第三方真实成功记录时不可写“已联调” |
| MCP | 登记 HTTP 或 stdio；可达/离线反映探测结果，不能把程序存在当成工具握手 |
| DDD | 添加规范术语和不推荐别名；需求或节点使用别名时出现 R6/DDD_DRIFT Warning |
| 工程规则 | 保存禁止命令片段；下一次调用立即检查；严格模式需先有人工授权 |
| 扩展检查 | 选择强化路径，检查实际变更是否落在声明范围、有无敏感文件名；明确不是漏洞扫描 |
| 成本 | 按实际 usage 与保存的费率计算估算；缺失数据标未知；预算超出仅提示 |
| 工作区 | 登记已有 Git 仓库绝对路径；每个运行分支与目录独立；项目依赖由任务配置安装 |
| Doctor | 查看 Git 和能力探测，清理失效 worktree 登记，不删除有效产物 |

## 6. API 索引

原有 `/api/decompose`、`/decompose-nl`、`/plans` 和 `/runs/:id?since=` 保留。新管理路由需要 `Authorization: Bearer <local-session-token>`，浏览器同源引导后由 Axios 自动携带。

| 路由 | 用途 |
| --- | --- |
| POST `/api/goals/parse`、`/goals/validate`、`/goals/confirm` | 契约提取、结构验证、来源确认 |
| POST `/api/workflows/compile`、`/validate`、`/impact` | 编译、三级校验与影响报告 |
| GET `/api/workflow-presets`；POST `/api/workflows/demo` | 原创示例与真实演示仓库 |
| POST `/api/workflows/export`；GET `/api/plans/:id/export` | 三种计划导出 |
| POST `/api/plans/:id/trial`；GET 同路径 | 隔离试跑与报告；可传 failures 节点次数模拟失败 |
| POST/GET `/api/plans/:id/versions`；GET `/:versionId` | 发布、列表、读取不可变版本 |
| POST `/api/plans/:id/execute` | 指定 versionId/workspaceId/inputs 启动；完整运行需鉴权 |
| POST `/api/runs/:id/pause,resume,retry,resolve,ghost,restore` | 各自为独立路径的运行控制 |
| GET `/api/runs`、`/runs/:id`、`/resources` | 历史、增量运行事件与资源池 |
| GET `/api/runs/:id/sessions/:sessionId`、`/evidence` | 会话与证据附件 |
| GET `/api/evidence/search?q=...`、`/audit?since=...` | 检索和设计账本增量分页 |
| GET/POST `/api/capabilities`、`/providers` | 能力与供应商管理 |
| POST `/api/capabilities/:id/probe` | 探测（内置 API 只检查配置） |
| GET/POST `/api/workspaces`；POST `/workspaces/demo` | 仓库登记与演示工作区 |
| GET/POST `/api/mcp`；POST `/mcp/:id/probe` | MCP 登记与连通性 |
| GET `/api/governance`；POST `/governance/terms`、`/governance/policy`；DELETE `/governance/terms/:id` | 术语及工程规则 |
| POST `/api/doctor` | 环境检查 |

## 7. 测试、发布包与限制

执行四项检查：`npm ci`、`npm test`、`npm run build`、`npm run test:e2e`。详细结果见最终验收报告；核心真实执行、Git、进程、API 和浏览器均有自动化覆盖。

`npm run package:web -- <不存在的绝对目录>` 生成可分发目录，接收方执行 `node start.mjs`。目录默认监听 127.0.0.1:3000，可配置 PORT 和 VTO_DATA_DIR。

本次没有使用真实供应商 Key 或第三方 CLI/ACP 授权账号；Windows/Linux 没有实机验收。不要把文件边界与 worktree 当成 OS 沙箱，不要把估算费用、模拟 Trial、固定演示产物或校验摘要当成外部业务成功证明。
