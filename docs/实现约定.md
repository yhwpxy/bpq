## 数据与行为细节

- `Plan.version` 为 `1.0`。Run 与 TaskSpec 沿用 6.4、6.5 的明确结构，不因 6.1 的概括文字额外增加 version 字段。
- 存储根目录采用 8.1 的 `backend/storage/`，6.6 的 `server/storage/` 视为逻辑示意。方案索引与运行快照结构保持不变。
- `props.name` 作为可选显示名称也保留在由清单生成的条件、延时和结束节点上，确保改名可以在画布和重新加载后显示；行为仍仅由其类型及 expression/wait 等既有属性决定。
- 名称长度按 Unicode 字符计数。文件大小按 UTF-8 字节，200KB 为 204800 字节。任务清单最多转换成 100 节点、200 边。
- 没有动作关键词且包含子条目的 Markdown 标题用作分组容器，列表或编号条目作为任务。命中动作关键词的父标题可成为节点，子条目依赖它。叙述段落、代码块不作为任务。
- 英文 Markdown 可以识别结构并生成普通任务，语义关键词仍以说明书中文规则为准。重复编号或未绑定条件的分支后缀返回 40003；缺一侧分支保留预览，生成/执行前提示修正。
- 自动条件默认引用 `passed`，后续独立条件使用 `passed_2` 等变量，前一个普通任务成功后输出对应变量。确认表可修改表达式与输出变量；不会推断真实认证业务。
- 清单取消勾选会跨过被省略条目，保留其上游依赖；删除条目时清理依赖。缺失分支或循环依赖会明确提示，不静默生成无法运行的图。
- 未指定任务耗时默认 800ms、重试 0、失败率 0，延时默认 1000ms。并发数限定为 1～100 的整数，默认 3。
- 表达式使用严格类型比较；未定义变量读取为 undefined，最终结果转为布尔值。禁止函数调用、赋值、属性访问和危险变量名。
- 条件分支以边信号区分“未激活”与“上游失败”，避免嵌套分支中未激活的汇聚点意外执行。continueOnError 只忽略失败，不激活未选择的条件分支。
- 停止时将未开始和仍在执行的节点统一标记 CANCELED，并取消等待，防止出现迟到的成功状态。重启服务后读取未结束的运行会标记为 FAILED，并记录服务重启原因。
- 完成运行通过保存的 runId 恢复，接口不新增运行列表端点。500ms 增量轮询只访问本地 API。
- 首次 npm 安装需要网络。完成依赖安装后，开发和构建产物均可离线运行，不加载 CDN 字体、脚本或外部 API。
