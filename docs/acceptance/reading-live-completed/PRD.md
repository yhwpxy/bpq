## 背景与目标

用户要做一个仅自己使用的中文读书清单网页，解决已读与想读混在备忘录里难查找的问题。首版支持四项操作：添加书籍、切换已读/未读、按状态筛选、删除书籍；刷新后数据保留。范围限定单用户、桌面优先、零服务器成本、一周内交付、最多 500 本。已附条件批准，条件要求在需求中明确：顶部单标签提示文案、满额时隐藏旧书名校验错误、只读态不提供应用内修复、完整 UUID 不截断、状态区位于筛选条上方、环境缺失按能力区分。

- 做一个仅自己使用的中文读书清单网页，解决已读与想读混在备忘录中难以查找的问题。
- 支持添加书籍、切换已读/未读、按阅读状态筛选、删除书籍四项操作，刷新后数据保留。
- 在零服务器成本、一周内交付、最多 500 本的约束下完成首版，桌面浏览器优先，文字清楚、操作简单。

## 用户与场景

- 用户在输入框输入书名并提交，清单新增一条未读书，刷新后仍在。
- 用户点击某行的“标记为已读”，该行状态更新；在未读筛选下该行移出视图。
- 用户切换到已读筛选，只看到已读书；刷新后回到全部筛选。
- 用户点击删除，浏览器原生确认框显示书名与完整 ID；取消则无变化，确认后条目消失且刷新不恢复。
- 清单恰好 500 本时再提交，仅提示已达上限，且不显示书名校验错误。
- 浏览器数据损坏或记录不合法时，整表进入只读错误态：不渲染部分条目，添加/切换/删除全部禁用，原值不被覆盖。
- 只支持 crypto.randomUUID 缺失但存储正常的环境时，可查看并可切换、删除已有条目，但无法新增。

## 方案摘要

用户要做一个单用户、中文、桌面优先的读书清单网页：输入书名添加书，每行按钮切换已读/未读，按全部/已读/未读筛选，删除前用浏览器原生确认框。数据以单键 JSON 数组存 localStorage，刷新保留；页面顶部以普通文档流说明数据仅存当前浏览器、清理浏览器数据会丢失、仅单标签使用。所有写操作先写存储成功再更新界面，失败保持原界面并提示保存失败。运行前提为支持 localStorage 与 crypto.randomUUID 的现代桌面 Chrome/Edge，经 HTTPS 或 localhost 打开。已由用户裁决关闭全部待确认项，本轮整合不再重复确认。

- 三类写操作（新增/切换/删除）统一流程：先 setItem 成功，再更新界面；失败时界面保持原样、显示保存失败，成功后清除该提示。
- 整表加载先校验：任一条件不满足即进入只读错误态，不渲染部分条目、禁止三类写操作、不覆盖原值、不判满额。
- 提示按优先级显示在页面顶部状态区：只读错误 > 本次保存失败 > 已满 500 本；输入校验错误单独显示在输入框旁。
- 列表按添加时间降序、同时间按完整 ID 字典序升序排列；筛选只改视图、不写存储，刷新回到全部。

- 范围外 · 移动端专项适配与窄屏布局。

- 范围外 · 只读错误态下的解锁、清空、修复、恢复或二次覆盖确认功能。
- 范围外 · 筛选计数展示、切换后“已移出当前视图”专门提示、全空与筛选无结果两套空态文案。
- 范围外 · 删除成功提示、撤销删除、批量删除、页面内自定义确认层。
- 范围外 · 实时字数提示与替代 ID 生成方案（维持 crypto.randomUUID）。
- 为稳妥避免“界面显示已保存但刷新丢失”，接受写成功仅以 setItem 未抛异常为准，不承诺防浏览器清理或静默丢盘。
- 为控制范围与工期，列表直接展示完整 ID（crypto.randomUUID 生成），可区分同名但较长，不另设短编号或落库序号。
- 为简化首版，不做跨标签同步；接受两个标签页同时编辑可能互相覆盖的风险。
- 数据损坏时只进入只读错误态并要求用户自行修复，不提供跳过坏记录、清空或恢复入口，换取不误覆盖原值。
- 筛选与切换不设“移出视图”提示、不展示计数，减少界面状态与验收面，代价是用户需通过切换视图确认结果。

## 业务规则

- 书名提交时 trim 去首尾空白，为空（含纯空格）拒绝并提示“请输入非空书名”，保留输入。
- 书名长度按 trim 后 Unicode 码点计 1–100，允许内部空格，不做实时字数提示。
- 允许同名书，所有定位与操作按唯一内部 ID，不按书名匹配。
- 新书默认未读，添加时间取 Date.now，ID 用 crypto.randomUUID。
- 列表排序：添加时间降序，同时间按完整 ID 字典序升序；切换与筛选不改变该顺序。
- 筛选为全部/已读/未读三选项，初始全部，不持久化，刷新回到全部。
- 删除确认显示书名与该行完整内部 ID，取消无变更，确认后按 ID 删除。
- 满额判断先于输入校验；满额时只提示上限，不触发书名校验错误。
- 只读错误态下不判满额、禁止三类写操作、不覆盖或清理原值。
- 写成功清除本次保存失败提示；输入校验错误不占顶部状态区。

## 约束与外部依赖

- 数据仅存当前浏览器 localStorage，单键 JSON 数组，刷新保留；清理浏览器数据会丢失，不宣称可防丢失。
- 三类写操作必须先写存储成功再更新界面；失败时保持原列表、当前筛选与已填书名/输入，并提示保存失败。
- 运行前提：支持 localStorage 与 crypto.randomUUID 的现代桌面 Chrome/Edge，经 HTTPS 或 localhost 安全上下文打开，不支持 file://。
- 满 500 本按全部记录计数，恰好 500 条禁止新增；501 条属只读错误态不可写入。
- 提示优先级：只读错误 > 本次保存失败 > 已满 500 本；输入校验错误单独显示在输入框旁。
- 列表与删除确认框展示同一完整内部 ID，用于区分同名书。
- 中文界面，桌面优先，文字清楚、操作简单，零服务器成本，一周内交付。
- 浏览器 localStorage（数据持久化，单键 JSON 数组）。
- 浏览器 crypto.randomUUID（新增记录 ID 生成），要求安全上下文（HTTPS 或 localhost）。
- 现代桌面 Chrome 或 Edge 浏览器，支持上述 API 与 ES 模块脚本。
- 浏览器原生 confirm 确认框（删除确认，无第三方依赖）。
- localhost 静态文件服务（仅用于承载静态文件与满足安全上下文，不承担业务后端、数据库或付费预算）。

## 风险、假设与未决事项

- 用户清理浏览器数据或换浏览器/设备后清单全部丢失，只能靠页面顶部文案提前告知。
- 列出展示完整 UUID 降低可读性，长列表下辨识同名书仍可能费力。
- 单标签页假设若不慎多开，后写覆盖先写，用户可能察觉数据回退。
- 浏览器存储配额耗尽或存储被禁用时新增失败，属保存失败路径，用户需自行清理。
- crypto.randomUUID 或 localStorage 不可用（如旧浏览器、非安全上下文、file:// 打开）时无法新增，仅已有合法数据可查看、切换、删除。
- 数据被外部程序或手工编辑损坏时整表进入只读错误态，首版无应用内修复手段。
