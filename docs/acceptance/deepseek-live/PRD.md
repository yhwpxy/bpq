## 背景与目标

用户要做一个仅本地、离线使用的单页物品计数器，替代心算，随时一眼看到当前件数。方案已获有条件批准：本次只形成需求基线，不声称应用已开发或测试完成；实现与浏览器实测留待下游交付验收。清零从 9999 回到 0 后按钮联动列为必须验收；禁用外观由验收人并排目视判断并记录结论，不设对比度数值门槛；各浏览器验收记录字段须写入需求。

- 做一个仅本地离线使用的单页物品计数器，替代心算，随时一眼看到当前件数。
- 页面居中大号显示当前件数，初值 0；点击增减后立即更新，不使用动画。
- 提供“加一/减一/清零”三个中文按钮，始终可见；每次点击只改变 1。
- 数值限定 0–9999，边界处对应按钮禁用且禁用状态可辨；清零前用浏览器原生确认框防误操作。
- 在约定环境（稳定版 Chrome/Edge 桌面、内容视口 1280×720、经本机静态服务器）下无滚动即可看到数字与三按钮。

## 用户与场景

- 首次经本机静态服务器打开页面：大号数字显示 0，“减一”禁用，“加一”“清零”可用。
- 连续点击“加一”观察数字每次只加 1；点“减一”观察每次只减 1。
- 数值为 0 时重复点击“减一”：数值保持 0；数值为 9999 时重复点击“加一”：数值保持 9999。
- 点击“清零”弹出原生确认框“确定清零吗？”：确认后归零，取消或 Esc 后数值与按钮状态不变；值为 0 时点击也照常弹框。
- 值从 9999 经清零确认后：数字为 0、“加一”可用、“减一”禁用。
- 按内容视口 1280×720、缩放 100% 检查：横纵均无滚动，标题、数字与三按钮同屏；并排目视记录禁用按钮是否可辨。
- 刷新页面回到 0；验收记录填写 Chrome 与 Edge 版本号及各记录字段，版本号缺失即验收不完整。

## 方案摘要

用户要做一个仅本地、离线、单页的物品计数器，用于手动清点物品：大号居中数字显示当前件数，三个中文按钮“加一/减一/清零”始终可见；每次点击只增减 1，范围 0–9999，0 时“减一”禁用、9999 时“加一”禁用；“清零”弹出浏览器原生确认框，文案“确定清零吗？”，确认归零、取消不变，0 时也可操作；刷新从 0 开始，无存储与恢复。已确认的验收口径：1280×720 指浏览器内容视口（不含地址栏等界面），横纵均无滚动且数字与三按钮同屏；仅需经本机静态服务器访问，不要求双击 HTML；原生确认框只验文案与确认/取消结果，浏览器按钮语言与样式不限；验收记录写明测试时 Chrome 与 Edge 版本号，不做版本检测。

- 单页静态实现、无依赖与构建链，状态只保存在页面内存，所有改值路径（加一、减一、清零确认）统一刷新数字与按钮禁用状态，避免显示与禁用不一致。
- 清零只调用浏览器原生 confirm，不自建弹层、不新增撤销或二次确认。
- 布局按内容视口 1280×720 约束高度，以大号居中数字与三按钮同屏无滚动为硬口径，具体字号、字体、配色与间距由实现者选择。
- 验收按固定步骤执行：在稳定版 Chrome 与 Edge 桌面分别设内容视口 1280×720、缩放 100%，检查无滚动、同屏可见、边界禁用、清零确认/取消结果，并手工记录两浏览器版本号。

## 业务规则

- 当前件数初值 0，仅保存在页面内存，刷新即回到 0，不提供恢复。
- “加一”使当前件数 +1，“减一”使当前件数 -1，每次点击只改变 1。
- 值到 0 后“减一”禁用且再点击数值仍为 0；值到 9999 后“加一”禁用且再点击仍为 9999；从 9999 减一后“加一”恢复可用。
- “清零”在 0–9999 任意值下均可点击并弹出原生确认框，包括值为 0 时。
- 确认清零后显示 0 并同步按钮状态（“减一”禁用、“加一”可用）；取消或按 Esc 关闭则数值与按钮状态均不变。
- 除三个按钮外，页面无可改变数值的控件；显示数字不可编辑、不响应键盘或滚轮改值。
- 页面不显示也不检测浏览器版本；版本号仅由验收人手工抄录，缺失即判验收不完整。

## 约束与外部依赖

- 范围 0–9999 的整数闭区间；0 时“减一”禁用、9999 时“加一”禁用，边界处重复点击数值不变。
- 每次点击只改变 1，不做连发与快捷键；点击后无需等待即可看到新值。
- 界面为中文，标题固定“物品计数器”，确认框文案固定“确定清零吗？”，不做多语言。
- 仅验收稳定版 Chrome 与 Edge 桌面，经本机静态服务器访问；内容视口 1280×720、缩放 100% 下横纵均无滚动且数字与三按钮同屏。
- 验收记录必须包含两款浏览器版本号与视口、缩放、滚动、同屏信息；不做程序化版本检测。
- 本机静态服务器（用于访问页面，具体端口与目录由实现者或验收人选择并记录）。
- 稳定版 Google Chrome 桌面浏览器（验收记录需写明版本号）。
- 稳定版 Microsoft Edge 桌面浏览器（验收记录需写明版本号）。
- 浏览器原生 confirm 确认框（文案与语言由浏览器渲染，不额外依赖组件库）。

## 风险、假设与未决事项

- 1280×720 内容视口高度有限，若字号或间距取大，可能为消除滚动而压缩布局；需以“无滚动且数字与三按钮同屏”为硬口径调整。
- 清零后若只改数值而未同步刷新按钮状态，可能出现显示 0 但“减一”仍可点的短暂不一致。
- 仅靠按钮禁用拦截越界时，若存在脚本等间接赋值入口，仍可能产生越界值；需在改值处统一钳制。
- 浏览器原生确认框的按钮文字与样式不可控，用户可能对按钮语言有预期落差，但已确认不作为验收失败条件。
- 边界与居中判定若使用“大致”“明显”等词，不同验收人可能结论不一，需按已确认的可观察口径执行。
- 从 9999 清零确认后“加一”按钮状态只要求可用，尚未定义是否需在同一验收记录中单列该用例（现仅写入记录口径，未作为强制通过前提）。
- 禁用按钮“肉眼可辨”为最低口径，未定义具体对比度阈值；如后续需要可访问性标准，需另行确认。
